# 領域文件

本儲存庫採用單一領域（`single-context`）配置。以下規則說明工程技能探索程式碼時應如何讀取領域文件。

## 探索前的閱讀順序

- 閱讀根目錄 `CONTEXT.md`。
- 若根目錄存在 `CONTEXT-MAP.md`，依其指引閱讀與工作相關的各個 `CONTEXT.md`。
- 閱讀 `docs/adr/` 中與工作範圍相關的架構決策紀錄（ADR）。若日後改為多領域配置，也檢查 `src/<context>/docs/adr/`。

若上述檔案或目錄不存在，直接繼續工作，不特別回報缺少文件，也不事先建議建立。`domain-modeling` 技能會在術語或決策獲得確認後，按需建立文件；`grill-with-docs` 與 `improve-codebase-architecture` 等技能也可能透過它維護文件。

## 文件配置

```text
/
├── CONTEXT.md     # 全專案領域術語與背景
└── docs/
    └── adr/       # 已確認的架構決策紀錄
```

此配置代表文件日後的存放位置，不要求預先建立空白文件或虛構決策。

## 使用術語表中的名稱

在議題標題、重構提案、假設或測試名稱中提及領域概念時，沿用 `CONTEXT.md` 定義的名稱，避免改用術語表明確排除的同義詞。

若需要的概念尚未收錄，先確認是否引入專案未使用的名稱；若確有缺漏，記錄供 `domain-modeling` 後續處理。

## 明確指出 ADR 衝突

若輸出內容與既有 ADR 衝突，明確說明衝突與重新討論的原因，不直接覆蓋原決策。例如：「此提案與 ADR-0007 衝突；建議重新討論，原因是……」。
